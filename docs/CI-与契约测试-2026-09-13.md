# CI 与契约测试配置（一期 E4）

- 日期：2026-09-13
- 文件：`.github/workflows/ci.yml`
- 结论：**流水线已落地，但契约测试的「跑通」还需要两件仓库外的事** —— 一台与 NAS 同局域网的自托管
  runner，以及三个 Secrets。本机无法代跑，理由见文末。

## 1. 两个 job

| job | 触发 | runner | 内容 |
| --- | --- | --- | --- |
| `verify` | push / PR / 手动 | GitHub 托管 `ubuntu-latest` | `pnpm install --frozen-lockfile` → `pnpm typecheck` → `pnpm test` |
| `contract` | **仅手动**（勾选 `run_contract`） | 自托管 `[self-hosted, nas-lan]` | `pnpm test:contract` |

为什么 `contract` 不放在 push 上：

1. **网络**：契约测试打的是局域网 `http://192.168.2.100:5666`，GitHub 托管 runner 到不了，
   必须用与 NAS 同网段的自托管 runner。
2. **副作用**：契约测试会真的写服务器 —— 播放上报会往播放历史里插记录、歌词偏移用例会改服务端
   的 offset 字段（用例内部会还原成 0，但仍是写操作）。放进 push 流水线等于每次提交都改 NAS 数据。
3. **稳定性**：NAS 可能关机 / 换 IP，不该因此让业务代码的 CI 变红。

## 2. 需要配置的内容

### Secrets（仓库 Settings → Secrets and variables → Actions）

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `FNOS_BASE_URL` | `http://192.168.2.100:5666` | **服务器根地址，不带 `/music/api/v1`** —— 客户端会自己拼前缀（见 `client.ts` 构造函数）。填成 `.../music` 会导致 404 |
| `FNOS_USERNAME` | `test` | 契约测试会断言 `/user/me` 与登录用户一致 |
| `FNOS_PASSWORD` | （测试账号密码） | 只用于 `sha256` 后登录，不落日志 |

### Variables（可选）

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `FNOS_CONTRACT_MUTATE` | `1` | 设成 `1` 才会跑「收藏写入与撤销」用例；默认不设，跳过 |

### 自托管 runner

在局域网内一台常开的机器（NAS 本身也可以）上注册 runner，并打标签 `nas-lan`：

```bash
# 在 GitHub 仓库 Settings → Actions → Runners → New self-hosted runner 里取命令，形如：
./config.sh --url https://github.com/<owner>/<repo> --token <TOKEN> --labels nas-lan
./run.sh          # 或 ./svc.sh install && ./svc.sh start 注册成服务
```

runner 上需要 Node 22 与 pnpm（`pnpm/action-setup` 会自动装 pnpm，但 Node 建议预装以免每次下载）。

## 3. 手动触发方式

```bash
gh workflow run CI --field run_contract=true
gh run watch
```

或在 GitHub 网页 Actions → CI → Run workflow → 勾上 `run_contract`。

## 4. 为什么本机无法代跑

- **没有 `.github` 目录、也没有 git remote**：这个仓库目前只是本地 git 仓库（`git remote -v` 为空），
  流水线文件是给「将来推到 GitHub」准备的，现在推不上去也就无法触发。
- **契约测试需要真实 NAS**：本机不在 `192.168.2.100` 所在局域网内，无法代跑。

因此 E4 的**可交付部分**（流水线定义 + 触发条件 + 凭据契约 + 环境校验步骤）已完成并入库；
**跑通**需要用户在仓库侧补 Secrets 与 runner，之后按上一节手动触发即可。

## 5. 顺带修掉的一个隐患

`docs/0号实测报告` 里记录的 `add-track` 返回成功但不持久化、`playlistTracks` 读返回 100002，
这两条**只会在契约测试或真机操作时才暴露**。把契约测试接进流水线之后，这类「接口漂移 / 后端 bug」
在手动触发一次就能发现，不必等真机回归。
