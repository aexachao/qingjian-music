## 1. F1 明文 HTTP —— 原实现是无效的（重要）

### 问题

`app.json` 里写的 `android.usesCleartextTraffic: true` **不会生效**。

证据：

```bash
# Expo 的 config schema 里根本没有这个键
$ grep -rn "usesCleartextTraffic" apps/mobile/node_modules/@expo/config-types/build/ExpoConfig.d.ts
# 无匹配
$ grep -rl "usesCleartextTraffic" apps/mobile/node_modules/@expo/ apps/mobile/node_modules/expo/
# 无匹配

# 而且 prebuild 出来的清单里确实没有这个属性（修复前）
$ grep -o 'android:usesCleartextTraffic="[^"]*"' apps/mobile/android/app/src/main/AndroidManifest.xml
# （空）
```

Expo 会**静默忽略**未知配置键，所以「配了」和「没配」在 Android 上完全一样：
Android 9（API 28）起默认禁止明文 HTTP，而本 App 的核心场景就是连局域网
`http://192.168.x.x:5666` —— 也就是说 Android 端**根本连不上服务器**，一期上架直接阻塞。

### 修复

新增 config plugin `apps/mobile/plugins/with-android-cleartext.js`，用 `withAndroidManifest`
把 `android:usesCleartextTraffic="true"` 写进 `<application>`；同时在 `app.json` 的
`plugins` 里注册，并**删掉那个无效的 `android.usesCleartextTraffic` 键**（避免留下误导）。

验证（修复后重跑 `expo prebuild`）：

```bash
$ npx expo prebuild --platform android --no-install
$ grep -o 'android:usesCleartextTraffic="[^"]*"' apps/mobile/android/app/src/main/AndroidManifest.xml
android:usesCleartextTraffic="true"        # ✅ 现在真的写进去了
```

### 安全权衡（记录在案）

这里放开的是**全量**明文，而不是只允许私有网段。原因：自建服务器可能用自定义域名 + http，
收窄到 `192.168/10/172.16-31` 会让这类用户直接不可用。明文流量仍受「必须用户主动填写
服务器地址」约束，App 不会自动发起任何明文请求。

> 如后续要收窄，可改为 `android:networkSecurityConfig` 指向一份只放行私有网段的
> `network_security_config.xml`；改动点只在同一个 plugin 内。

## 2. F2 system-volume 的 Android 真实现

改动前：`modules/system-volume/index.android.tsx` 只是「改内存变量」的桩，`addVolumeListener`
是 no-op，`expo-module.config.json` 的 `platforms` 只有 `apple` —— 音量条在 Android 上完全无效。

改动后：

| 文件 | 作用 |
| --- | --- |
| `modules/system-volume/expo-module.config.json` | `platforms` 加 `android`，注册 `expo.modules.systemvolume.SystemVolumeModule` |
| `modules/system-volume/android/build.gradle` | 与 `app-icon` 同一套 `expo-module-gradle-plugin` 配置 |
| `modules/system-volume/android/src/main/AndroidManifest.xml` | 空清单（模块不需要额外权限） |
| `modules/system-volume/android/src/main/java/expo/modules/systemvolume/SystemVolumeModule.kt` | 真实实现 |
| `modules/system-volume/index.android.tsx` | 改为连真实原生模块（与 iOS 入口同一份 JS 契约） |

实现要点：

- `getSystemVolume`：`AudioManager.getStreamVolume(STREAM_MUSIC) / getStreamMaxVolume(STREAM_MUSIC)`，
  **归一化到 0..1**，与 iOS 的 `AVAudioSession.outputVolume` 语义对齐，上层音量条逻辑两端共用。
- `setSystemVolume`：`setStreamVolume(STREAM_MUSIC, target, 0)` —— **flags 传 0 才不弹系统音量 HUD**，
  这是 Android 侧「静默改音量」的等价手段（iOS 那边要靠幽灵 `MPVolumeView`）。
- `addVolumeListener`：监听系统广播 `android.media.VOLUME_CHANGED_ACTION`（隐藏常量，用字面值），
  只透传 `EXTRA_VOLUME_STREAM_TYPE == STREAM_MUSIC` 的事件；Android 13+ 用
  `Context.RECEIVER_NOT_EXPORTED` 注册，13 以下走旧签名。
- `SystemVolumeSlider` 在 Android 渲染 `null`：不需要幽灵视图（调用方本来就以
  `absoluteFill` + `pointerEvents="none"` 包着它，渲染 null 无副作用）。

自动链接已验证：

```bash
$ npx expo-modules-autolinking search --platform android
'system-volume': { ... config: { platforms: ['apple','android'],
  android: { modules: ['expo.modules.systemvolume.SystemVolumeModule'] } } }   # ✅ 已被识别
```

## 4. F5 Android 存储与权限核对

| 用途 | 目录 | Android 落点 | 是否需要权限 | 是否会被系统回收 |
| --- | --- | --- | --- | --- |
| 音频播放缓存 | `Paths.cache/audio` | `/data/user/0/<pkg>/cache` | ❌ 不需要 | ✅ 会被回收 |
| 歌词缓存 | `Paths.cache/lyrics` | 同上 | ❌ 不需要 | ✅ |
| 封面缓存 | `Paths.cache/artwork` | 同上 | ❌ 不需要 | ✅ |
| 播放快照 | `Paths.document` | `/data/user/0/<pkg>/files` | ❌ 不需要 | ❌ 不会被回收 |

- 全部落在 **app-specific 内部目录**，因此**不需要任何存储权限**。清单里的
  `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` 来自 Expo 模板且都带
  `maxSdkVersion="32"`，代码里没有任何消费方，属于无害的模板残留。
- `expo-file-system` SDK 57 只暴露 `Paths.cache` / `Paths.bundle` / `Paths.document`
  （已核对 `Paths.d.ts`），**没有** Android 的 `getNoBackupFilesDir` 等价物。

### ⚠️ 二期必须先解决的问题：Android Auto Backup 会吞掉离线音乐

清单里是 `android:allowBackup="true"`（Expo 模板默认）。Android Auto Backup 会包含
`files/`（也就是 `Paths.document`），默认上限 25MB。

- **现在没问题**：`Paths.document` 只放一个很小的播放快照 JSON。
- **二期会出问题**：二期计划把离线下载放到 `Paths.document/downloads`，几十 GB 音频会被纳入
  备份并被 25MB 上限截断 —— 用户在换机恢复时会拿到**残缺的音频文件**，且没有报错。

这与 `docs/设计补充2` 里已经记录的 iOS「`Paths.document` 会被 iCloud 备份」是**同一类问题**，
但 Android 侧的解法不同：需要加 `android:dataExtractionRules` / `android:fullBackupContent`
把 downloads 目录排除掉（`expo-file-system` 不提供该能力，得写原生 config plugin）。

**建议**：二期做「离线存储分层」时，把「Android 备份排除」和「iOS 备份排除」合并成一个
`modules/file-backup-exclusion` 原生模块一次性做完，不要分成两次。

## 5. F3 构建与真机验证 —— 本机未执行（需要环境）

### 现状

本机**没有** Java 运行时、没有 Android SDK、没有 Android Studio：

```bash
$ java -version
The operation couldn't be completed. Unable to locate a Java Runtime.
$ ls ~/Library/Android/sdk
no android sdk
$ which adb sdkmanager gradle
（都没有）
```

因此 `gradlew assembleDebug` 与真机跑通**无法在本机完成**。已完成的部分是
`expo prebuild`（只依赖 Node）与静态核对，即上文 1–4 节。

### 环境就绪后按顺序执行

```bash
# 0) 安装 JDK 17+ 与 Android SDK（含 platform-tools / build-tools / platform 36），
#    并设置 ANDROID_HOME；或直接安装 Android Studio。
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$PATH"

cd /Users/chrisli/Documents/dev/qingjian-music/apps/mobile

# 1) 重新生成原生工程（改了 app.json / plugin / 原生模块后必须跑）
npx expo prebuild --platform android --no-install

# 2) 确认 cleartext 真的在清单里（这一步不能省，历史上就栽在这）
grep -o 'android:usesCleartextTraffic="[^"]*"' android/app/src/main/AndroidManifest.xml

# 3) 构建并安装到真机
npx expo run:android --variant debug

# 4) 真机验证清单（逐条打勾，任一不过就说明该功能在 Android 上没落地）
```

### 真机验证清单

1. **连服务器**：填 `http://192.168.2.100:5666/music` 能登录（这一条直接验证 F1）。
2. **播放**：能起播、能切歌；通知栏出现播放控制，锁屏能暂停/下一首（验证 RNTP 前台服务）。
3. **后台保活**：退到后台 5 分钟仍在播，通知栏常驻。
4. **音量条**：播放页音量条拖动时**系统音量真的变化**，且**不弹系统音量 HUD**（验证 F2）。
5. **音量联动**：按手机音量键，App 内音量条跟着动（验证广播监听）。
6. **转码兜底**：播一首 WMA/APE，能自动走 HLS 转码播放。
7. **图标切换**：设置 → 外观 → 换图标，桌面图标立即变化（验证 activity-alias）。
8. **深链**：`adb shell am start -a android.intent.action.VIEW -d "qingjianmusic://home"` 能打开 App。
9. **缓存与存储**：设置里清缓存有效；`adb shell du -sh /data/user/0/com.chrisli.music/cache` 能看到缓存增长。
10. **Android 14+ 权限**：不申请存储权限也能正常播放与缓存（验证 F5 结论）。

### 已知需要在真机上才能确认的残留风险

- `VOLUME_CHANGED_ACTION` 是 hidden 常量：各厂商 ROM 上是否都发这个广播需要真机确认；
  代码里已做 `try/catch` 降级（收不到广播时音量条仍可读写，只是不跟随音量键）。
- `MusicService` 在 RNTP 库清单里是 `android:exported="true"`，属上游设定，上架前需再评估。
- Android 13+ 通知权限（`POST_NOTIFICATIONS`）未在清单中显式声明；Expo 默认模板不带，
  若真机上通知栏不显示播放控制，需要补该权限并在运行时请求。
