# 网络恢复与蜂窝播放（2026-09-29）

> 时点快照：记录当时的实现与验收情况，当前状态以代码和现状基线为准。

> 后续发布：本报告改动已随 [TestFlight 0.1.4（44）](./TestFlight-0.1.4-44-2026-09-29.md) 推送到公开测试组，状态为 `IN_BETA_TESTING`。下文保留实现完成时的验收记录。

## 状态与适用范围

本轮为轻简音乐增加网络恢复与蜂窝播放设置，重点验收 iPhone。代码已在本地完成；本轮没有上传 TestFlight。已发布的 0.1.4 (43) 不包含本轮功能，也不包含随后完成的歌词动画优化。

原实现遇到网络错误主要显示提示；不能保证断网恢复后重新解析过期音频 URL、恢复转码会话并从中断位置继续。

## 最终行为

| 场景 | 处理 |
| --- | --- |
| 播放中断网 | 保留歌曲身份、播放意图和进度；允许已有缓冲继续播放，连接恢复后尝试续播。 |
| Wi-Fi 保持连接但音频持续缓冲 | 同一歌曲连续 Loading/Buffering 达到 20 秒后检查原生状态并尝试重建播放；重复缓冲事件不会延长计时。 |
| 网络恢复 | 若原生已经正常播放，不重载；否则重新解析 URL/转码会话，加载同一首并恢复进度。 |
| 恢复命令已提交但仍缓冲 | 至少等待 20 秒确认窗口，避免每两秒重新加载打断慢网缓冲。 |
| 长期失败、网络反复变化 | 同一播放意图最多五次尝试，失败退避为 1/2/4/8/16 秒；单次异步恢复设 20 秒超时。达到上限提示手动重试，切网不重置次数。 |
| 用户暂停、切歌、登出 | 撤销旧恢复意图，旧异步操作不得拉回旧歌曲或擅自播放。 |
| 用户调整进度 | 拖动进度、歌词定位、锁屏定位统一取消旧恢复；目标时间随新意图传递。 |
| Wi-Fi 转蜂窝，设置关闭 | 提示并停止远程音频；保存 stop 前的进度，停止自动音频缓存和转码预热。 |
| Wi-Fi 转蜂窝，设置开启 | 提示正在使用移动流量，允许继续/恢复播放。 |
| App 在后台 | 前台提示延后到回到 App；iOS 原生音频蜂窝限制独立于 JS 提示。 |
| 本地音频文件 | 按原生实际 URL 判断本地来源，不受在线播放开关限制；缓存登记不再被误当作原生已使用本地文件。 |

设置入口：设置页 →「使用蜂窝网络播放」。默认关闭，持久化保存；初始化期间的用户修改不会被旧存储值覆盖。该开关控制在线音频播放及自动音频预取，不控制用户主动创建的下载任务，也不是整个 App 的全局移动流量开关。

Wi-Fi 即使没有公共互联网，也可能能访问局域网 NAS，因此不把 `isInternetReachable=false` 当成 NAS 必定不可达。网络类型未知时暂时禁止在线音频；类型查询最多等待 3 秒，晚到快照不能覆盖新网络事件。

## 实现与复查

- `playback-intent.ts`：把用户意图与原生 buffering/paused 状态分开；维护取消版本、手动定位目标及网络停止进度。
- `network-access.ts`：平台网络状态、查询超时和在线播放门禁。
- `network-recovery.ts`：监听连接、原生状态、播放进度、中断和设置；执行有上限的恢复和缓冲检测。
- `controller.ts`：所有主要播放/定位入口使用同一策略；手动跳转前检查实际原生目标 URL；恢复在每个异步提交边界检查是否仍为当前意图。
- `bridge.tsx`：先分类远程网络错误；等待后复查意图和待切换歌曲；同 QID 的原生资产重载不再重复记录播放、历史和口味信号。
- RNTP 持久补丁：iOS `AVURLAssetAllowsCellularAccessKey` 约束实际音频资源访问；设置修改时重建当前远程资产并保留位置及播放状态。本地资产不重建。
- 迷你播放器和全屏播放器在等待网络时保留可点击暂停按钮，用户可以取消续播。

独立代码复查发现并修复了：缓存登记与实际音频来源不一致、skip 先于门禁、坏本地文件被误归为网络故障、迟到 Playing 清掉恢复状态、旧超时干扰新意图、stop 后归零覆盖进度、恢复命令成功后过早再次重载、连续缓冲事件推迟 watchdog 等问题。最终静态复核未发现新的阻断项；主线程复查了最终控制器、恢复器及原生补丁。

## 已知边界与后续验收

1. **恢复是有条件的尝试。** 网络恢复但服务器仍不可达、登录失效、或 NAS 仅有局域网地址时不能保证续播；五次失败后需要手动重试。
2. **离线混合列表仍有原有局限。** 队列构建会为远端待播项提前请求 URL，因此「已下载的当前曲目 + 未缓存的后续曲目」整批离线点播仍可能在建队列阶段失败。解决需要单独调整为惰性队列解析，本轮没有扩大此处架构。
3. **Android 尚无等价的原生蜂窝硬限制。** JS 已在手动跳转前拦截并在自然换曲时检查，但自动切至已入队远端曲目可能存在短暂请求窗口。本轮通过的原生构建与强制音频流量约束是 iOS；不能据此承诺 Android 零蜂窝音频请求。
4. **原生错误事件没有 QID。** JS 能丢弃等待期间失效的错误，但如果旧错误到新曲完全提交之后才投递，仍无法绝对证明其来源；以后可在原生层增加事件身份。
5. **同 QID 激活副作用经过静态复查，尚无独立 bridge 事件运行测试。** 真机应核对开关切换不会增加历史/播放次数。

下一次真机验收：播放至中段 → 断网 → 恢复 Wi-Fi；Wi-Fi → 蜂窝（开关分别关/开）；等待恢复时暂停/切歌/定位；蜂窝阻止后暂停再播放；锁屏重复上述路径；NAS 不可达时确认重试上限和手动重试提示。验收时同时观察进度保持及服务器音频请求。
