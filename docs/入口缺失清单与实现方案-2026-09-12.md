### A1 「添加到歌单」—— ✅ 已完成（2026-09-12）

| 项 | 内容 |
| --- | --- |
| 位置 | `components/track-more-button.tsx`、`components/player/player-deck.tsx` |
| 原现状 | `case 'add-to-playlist': toast('已添加到歌单')` —— **没有任何网络请求** |
| 用户感知 | 看到「已添加到歌单」，去歌单里找却没有 → 会认为 App 有 bug 或数据丢了 |
| 根因 | 契约层 `MusicProvider` 无歌单写方法，但 `capabilities.playlists='write'` 已声明、端点已备好 |
| 实施 | `provider-api` 加 `addTracksToPlaylist`；`provider-fnos` 实现 `POST /playlist/add-track`；新增 `components/playlist-picker-sheet.tsx` 底部歌单选择器（拉取歌单列表 → 选择 → 调用 → 刷新缓存）；菜单从假 toast 改为打开选择器 |

**实现方案**

1. `packages/provider-api/src/provider.ts` 新增：
   ```ts
   addTracksToPlaylist?(playlistId: string, trackIds: string[]): Promise<void>
   ```
2. `packages/provider-fnos/src/provider.ts` 实现：`POST /playlist/add-track {guid, trackGUIDs}`；返回体宽松解析（`z.unknown()`）；错误码映射 `100005` → notFound、`100002` → invalidArguments
3. 新建 `components/playlist-picker.tsx`（或复用现有 `components/option-picker-modal.tsx`）：
   - 拉 `provider.playlists({ page: 1, size: 100 })` 列出歌单
   - 顶部一个「新建歌单」项（与 A 组的一期「歌单新增」共用 `PromptModal`）
   - 空态：「还没有歌单，点这里新建」
4. 两处 handler 改为：
   ```ts
   case 'add-to-playlist':
     setPickerTrack(track)   // 打开选择器
     break
   ```
   选择后调用 `addTracksToPlaylist` → 成功 `toast('已添加到「歌单名」')`，失败 `toast(错误信息)`
5. **反馈闭环要点**：
   - 成功后 `queryClient.invalidateQueries({ queryKey: ['playlist-tracks', connection.id, playlistId] })`
   - **曲目已在目标歌单时应显示「已在歌单中」而不是重复添加**（需要先查 `playlistTracks` 或在服务端返回重复时提示）
   - 失败必须给可读原因（重名/无权限/网络），不能只 toast「失败」

### B1 「分享歌词」

| 项 | 内容 |
| --- | --- |
| 位置 | `components/player/player-deck.tsx:485-489` |
| 现状 | 菜单叫「分享歌词」，实际只分享 `《标题》- 艺术家\n(分享自轻简音乐)` —— **一个字歌词都没有** |
| 用户感知 | 分享出去对方只看到歌名，会以为歌词没加载出来 |

**实现方案**

1. 复用已有的 `useLyricSheet(trackId)`（`lib/lyric-offset.ts:21`，React Query 30min 缓存，与歌词页共用同一份）
2. handler 改为 async：
   ```ts
   case 'share-lyrics': {
     const sheet = await queryClient.fetchQuery(lyricQueryOptions(current.trackId))
     const lines = sheet?.lines.map((l) => l.text).filter(Boolean) ?? []
     if (lines.length === 0) { toast('这首歌还没有歌词'); break }
     const body = lines.slice(0, 40).join('\n')
     const truncated = lines.length > 40 ? `${body}\n…（共 ${lines.length} 行）` : body
     void Share.share({
       title: `${current.title} 歌词`,
       message: `《${current.title}》- ${current.artistText}\n\n${truncated}\n\n(分享自轻简音乐)`,
     })
     break
   }
   ```
3. **注意**：`handleAction` 目前是同步函数，改成 async 后要确认菜单关闭动画不被阻塞（`setIsMenuOpen(false)` 仍放在最前）
4. 逐字歌词的 `lines[].text` 已在 `parseLyrics` 里用 `body.replace(WORD_TAG, '')` 去掉了时间标签（`packages/provider-fnos/src/mappers.ts:186`），**可直接用，无需额外清洗**
5. 截断上限（40 行）是为了避开微信等平台的分享长度限制

| 规模 | 归属期 |
| --- | --- |
| S | **一期**（成本极低，且当前是**误导性文案**） |

### C2 「忘记密码」——✅ **已实施：移除死入口，引导移到失败态**

| 项 | 内容 |
| --- | --- |
| 位置 | `app/login.tsx`（原 `handleForgotPassword` + 辅助操作行的第二个 Pressable） |

| 问题 | 用户点它时的预期是「帮我找回/重置密码」，但结果是「你去别处弄吧」→ **点了没结果的死入口**。它占据了登录页最显眼的位置之一，却只服务于一个用户还没遇到的问题 |

**实施内容（已完成）**

2. **删除**随之失效的 `useConfirm` 导入、`const confirm = useConfirm()`、`forgotPasswordText` 样式（避免留下死代码）

5. 每次提交前重置 `showResetHint`，避免上一次的提示残留
6. 测试同步更新：`test/unit/login-interaction.test.ts` 改为断言 **「表单里不含 `忘记密码?` / `handleForgotPassword`」**，并断言新引导存在 —— 把这个决定固化成回归测试
