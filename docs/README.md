## 方案评估

| 文档 | 用途 | 关键结论 |
| --- | --- | --- |
| `方案评估-本地解码-vs-服务端转码-2026-09-13.md` | 评估「把不可播格式的转码搬到 App 本地做」 | **不建议做**：只对 ~5% 曲目、只在带宽单一维度占优（DSD 反而更差）；Hermes 无 WASM + RNTP/KotlinAudio 无解码器注入点 → 必然引入 FFmpeg 双端原生代码。建议改做「缓存服务端转码产物」（纯 JS，可单测）。**§8 已 spike 实测通过**：拼接产物 AVFoundation 可播且完整解码；并发现「分片顺序错时仍 isPlayable=true」必须靠时长交叉校验兜住 |

## 阅读建议

1. **新接手项目**：先读 `功能审计报告` → `分期路线图` → `入口缺失清单与实现方案`
2. **实施一期**：读 `分期路线图` 的「一期实施进度」表 → 查对应工作项的实现方案
3. **做 Android**：读 `Android-核对与验证-2026-09-13.md`（含 F1 踩坑与真机清单）
4. **做离线/外部歌词**：读 `设计补充2` 的约束与存储分层设计
5. **查 API 端点**：读 `fnos-music-api.md`
6. **做 UI**：读 `design-tokens.md` 获取颜色/排版/间距规范
7. **改架构契约测试**：读 `分期路线图` 末尾的「E5 迁移指引」
8. **想动播放架构（本地解码/换播放器）**：先读 `方案评估-本地解码-vs-服务端转码-2026-09-13.md`，里面记了触发条件与三条硬约束，避免重复讨论
