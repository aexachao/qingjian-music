参考文档描述**接口与规范**，只在协议变化时更新。

**不在本表里的**：`docs/` 下另有 12 篇带日期的内部过程文档（交接文档、分期路线图、技术评审、
代码评审清单、实测报告、审计报告、方案评估、设计补充、Android 核对、CI 与契约测试），
按 `.gitignore` 的「内部工程文档」一节**有意不随仓库发布**，只在本地保留。
它们描述的是**某个时点**的发现，不参与本表的角色划分。

## 校验入口

| 命令 | 跑什么 |
| --- | --- |
| `node scripts/verify.mjs` | 快速校验：架构守卫 → 文档事实守卫 → ESLint → 4 包类型检查 → 4 包单测 |
| `node scripts/verify-full.mjs` | 完整验收：快速校验 + SwiftLint 0 warning + iOS Release 设备版编译与产物校验 |
| `node scripts/verify.mjs --only <guard\|docs\|lint\|typecheck\|test>` | 只跑某一类 |
| `node scripts/guard-architecture.mjs` | 只跑架构守卫（项目特有约束，存量债务记在 `scripts/guard-baseline.json`） |
| `node scripts/check-docs.mjs` | 只跑文档事实守卫（`--update` 重写本文件生成块，`--self-test` 自检规则有效性） |
| `node scripts/verify-ios.mjs` | 只跑 iOS 侧：SwiftLint + `prebuild --clean` + `pod install` + Release 编译 + 产物校验 |
| `pnpm test:contract` | 契约测试，需真实 NAS 环境变量（CI 上仅手动触发，见 `docs/build-and-ci.md`） |

## 维护规则

1. **改了下面生成块里的任何一项**（脚本名 / Expo Module 增删 / CI job 增删 / **`app.json` 版本号** /
   依赖版本）→ 跑 `node scripts/check-docs.mjs --update` 重写生成块，然后提交。
   > 2026-09-14 踩过：改了 `app.json` 的版本号却忘了跑 `--update`，CI 里文档事实守卫直接拦下构建。
   > 守卫工作正常，是流程漏了一步 —— 所以把它写进这条规则里。
2. **加新的校验步骤** → 不要在 `README.md` / `CONTRIBUTING.md` / `docs/build-and-ci.md` 里写「N 项」。
   那个数字每次加步骤都会过期；只更新本文件「校验入口」一节的表格。
3. **不要在本文件写测试条数、行数、耗时** —— 它们无法机械校验，写进来必然漂移。
