# 网络设置、存储图表与服务器多线路

> 时点快照：记录当时的实现与验收情况，当前状态以代码和现状基线为准。

## 本轮交付范围

1. 设置首页使用“网络与播放”入口，摘要显示蜂窝播放开启状态；开关移入二级页。继续沿用默认关闭、Wi-Fi/蜂窝切换提示与本地播放不受限的规则。
2. 缓存 → 存储占用与清理顶部新增“详细存储情况”：按容量比例绘制横向分段条，单列图例显示已下载、音频与转码缓存、歌词缓存、封面缓存、系统与其他占用、可用空间。支持浅色/深色、动态字体、VoiceOver。
3. 网络与播放 → 服务器线路：同一服务器保存主线路及最多两条备用线路。新地址使用现有 token 验证当前用户，保存成功后才生效，不重建 provider 或播放队列。显示当前线路，允许移除备用线路。

## 统计口径

- 设备总容量/可用容量取 Expo FileSystem 的真实设备读数。应用分类来自已下载文件登记及音频、歌词、封面的已知目录；不递归扫描设备。
- 音频播放缓存和转码缓存共享目录，合并展示，避免重复计算。
- 系统与其他占用为剩余已用容量，包含其他 App、系统、本 App 无法单独量化的数据及图片库自身磁盘缓存；不将其声称为其他 App 的精确用量。
- 读取失败展示“未知”；设备容量不可用时隐藏比例条。零容量不会绘制虚假的最小宽度。跨时刻采样的比例限制在 0–100%。
- 仅页面聚焦时监听回前台刷新；清理操作完成后刷新。未展示页面不在回前台时扫描缓存。

## 切线与播放语义

- 备用地址必须通向同一服务器和账号。支持局域网 HTTP；公网要求 HTTPS。拒绝重复地址、账号密码 URL、查询参数与片段。
- GET 在网络失败、超时或 502/503/504 后尝试已保存的备用线路；401/403、业务错误和协议错误不盲目切线。并发失败合并探测，晚到的旧线路错误不反向切回。
- 探测请求有明确截止时间；全部不可用时失败，不无限循环或后台轮询。可用线路继续使用，只有它再失败才尝试其他线路。
- 原生音频请求不经过 JS HTTP 客户端，因此播放错误/持续缓冲时，续播流程单独确认线路、重新获取播放地址，并保留队列项和进度。暂停、切歌、退出登录会阻止迟到的续播。
- 本地下载/缓存不探测线路；蜂窝播放关闭时不能用线路探测绕过播放策略。
- 配置了备用线路后，首次 HLS 转码先做只读线路确认，再发送转码创建请求。普通写操作（收藏、删除等）不因网络错误自动重放。
- 路由恢复、HLS 清理与重新创建共享最多 45 秒的单次续播截止时间；持续缓冲检测和发出播放命令后的等待期仍为 20 秒。这是上限，不是固定延迟。

## 仍需真机验收的边界

- 当前改动不承诺线路切换完全无感；当前缓冲耗尽后，探测、重新转码和定位进度仍可能产生短暂停顿。
- 备用线路设置针对已有登录会话；没有可用 token 时，不向尚未验证的新线路发送密码进行首次登录。
- fnOS 转码接口按歌曲 guid 管理任务，没有独立服务端会话 ID。客户端可以控制任务所有权与请求顺序，但不能撤销已被服务端接收、随后超时的请求；极端情况下仍需下一轮恢复。
- 本轮使用自动化故障注入验证状态与并发，不等同于实体 iPhone 在不同 Wi-Fi/蜂窝运营商之间切换的实测。
