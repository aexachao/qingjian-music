# 歌词动画优化与验证（2026-09-29）

> 后续发布：本报告改动已随 [TestFlight 0.1.4（44）](./TestFlight-0.1.4-44-2026-09-29.md) 推送到公开测试组，状态为 `IN_BETA_TESTING`。下文保留实现完成时的验收记录。

范围：用户体验 TestFlight 0.1.4 (43) 后反馈歌词高亮、切换生硬。本轮修改尚未上传 TestFlight；构建 43 不包含这些修改。

## 已定位原因

1. `LyricView` 把依赖 `activeIndex` 的计算结果持续传给 `contentOffset`。每次高亮行改变都会改写原生滚动位置，然后 effect 才调用动画滚动。在当前 RN iOS Fabric 实现 `RCTScrollViewComponentView.mm:404`，这个属性变化会直接执行 `_scrollView.contentOffset = ...`，因此会出现提前跳位，也能绕过代码中的拖动保护。
2. 所有行的五个回调每次渲染都会重新创建，导致 `memo(LyricRow)` 失效；播放进度每 200 ms 更新，即使只是同一行内进度变化，也会重渲染整张歌词列表。
3. 高亮行同时进行 0.93→1 缩放、0.32→1 透明度和 8→0 垂直位移动画。单行位移叠加在列表滚动上，视觉节奏不一致；翻译颜色还是瞬时切换。
4. 逐字行离开高亮时立即卸载逐字节点，换回统一亮色的普通文本，但父级透明度仍在渐变，可能造成亮度突变。
5. 旧逻辑首次自然推进、倒退或跨多行 seek 会采用无动画定位。阅读冷却计时器还会捕获松手时的旧高亮行，3.5 秒后可能回到旧位置。

这些是代码与回归测试证据，不代表已经测量到真机掉帧或确认唯一性能瓶颈。

## 实施

- `contentOffset` 固定为挂载初值；播放页按 `trackId` 重建歌词组件，避免把上一首歌的初始位置带到下一首。首次定位/重新进入歌词页保留直接定位，其余跟随通过原生 `scrollTo` 动画完成。
- 保留 UIScrollView 原生拖动、惯性与回弹；自动跟随仍遵守交互锁，读取最新高亮行后再恢复跟随。隐藏/暂停时计时器不滚动。
- 行回调稳定化，真实 React 渲染测试验证普通 LRC 的同一句进度更新只重渲染父组件，换句只重渲染父组件和新旧两行。
- 移除行级垂直位移，缩放幅度改为 0.97→1，非高亮透明度改为 0.48，焦点采用 420 ms 缓出过渡，翻译颜色同步渐变；无时间戳歌词保持清晰。
- 自然换句时保留相邻逐字行文本树并渐隐。逐字节点只存在于当前行与前后相邻行，避免整首歌创建大量字符动画。倒退/重新进入该行时直接校准逐字进度，正常前进才插值。
- 点按歌词 seek 改为 `max(0, (lineAtMs - offsetMs) / 1000)`，与显示端 `positionMs + offsetMs` 相互对应，避免设置偏移后点击跳错时间。
- 原生自动跟随尊重“减弱动态效果”；修复底部工具栏间距变化时的闭包依赖。
- 新增固定版本的 `react-test-renderer` 与类型开发依赖，用真实 React 生命周期测试行为，仅模拟原生绘制；不进入生产依赖。

## 验证

- 初始 10 项行为测试在隔离的旧组件副本上运行：9 项失败、1 项通过；相同测试在修复组件上全部通过。旧组件临时测试副本已清理，日志保留于 `.cache/lyric-motion-20260929/baseline-tests.log`。
- 最终新增 13 项行为测试：固定初始位置、正反向动画、渲染次数、拖动锁、恢复最新行、暂停/继续、隐藏页、首次/相邻逐字节点保留、跨歌曲重新挂载、偏移 seek、底部间距、减弱动态效果、长歌词节点上限、倒退不反向扫亮（部分合并在同一测试）。
- 300 行 × 20 字的测试中，逐字动画节点最多 60 个，即最多三行；没有把这个测试结果当作真实内存/FPS 测量。
- 全项目测试：94 个测试文件、925 项通过，其中 mobile 81 文件/768 项。
- 四个包的 TypeScript 检查通过；架构与文档事实守卫通过。
- 本轮相关文件 ESLint 无错误；播放页有两项原有 warning。歌词组件及新增测试无 warning。未宣称全仓库 lint 清零。
- iOS Release（iphoneos）本地构建通过：`BUILD SUCCEEDED`。本轮仅做未签名编译验证，未归档上传；Metro 重新打包 2234 个模块，产物时间晚于最终源码修改。日志：`.cache/lyric-motion-20260929/ios-build.log`。

## 仍需真机体验确认

本轮单测不会模拟 UIScrollView 物理滚动、实际 UI 线程动画或真实屏幕帧率。应在下一次 TestFlight 装机后验证：普通 LRC/逐字/翻译歌词；自然换句；连续点击前后歌词；拖动后暂停/继续；歌曲切换；长歌词；系统减弱动态效果。当前仍使用非虚拟化 ScrollView，特别长的歌词依旧会一次创建全部行，后续是否需要虚拟化应以真机测量为依据。
