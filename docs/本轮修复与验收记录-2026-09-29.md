## Review 中追加纠正

- 锁屏封面缓存同步命中时，内层 finally 早于 inflight.set 执行，导致名额永久占用；已改为外层 await 后释放并增加回归。
- 歌词清理跳过 index.json 后再次读取旧索引，误报残留；已改成目录重建并增加持久索引回归。
- 收藏成功后的 refetch 会覆盖排队中的下一次乐观状态；已在回填后恢复最新意图。
- 转码会话远程 close 延迟不再阻塞下一首；心跳防重入，过期心跳不能关闭新的预热会话。
- 自动处理中断已由原生开启；移除 JS RemoteDuck 重复无条件续播，远程控制拒绝统一捕获。
- Android 下载完成广播的文件搬运改到串行后台执行器，避免大文件同步复制阻塞界面；若进程被回收，保留的系统临时文件和任务元数据交给下次启动恢复。此调整仍缺 Android 编译和设备验证。广播线程约束参考 [Android BroadcastReceiver 文档](https://developer.android.com/reference/android/content/BroadcastReceiver)。
- 下载管理页的“全部删除”限定当前展示服务器，避免按当前账号数量提示却删除其他账号的文件；删除失败展示真实错误。
- 认证刷新保存回调结束后再次检查注销代次，防止旧客户端重新拿回 token。
- 空列表播放不再进入永久 loading；播放器恢复的旧延时不再解除较新恢复过程的上报抑制。
- 对已经有行为测试覆盖的队列/循环/恢复逻辑，移除依赖精确源码字符串的重复断言；新增实际延迟和失败行为用例。

## 尚未获得验收证据的范围

1. **V1/V4：原生实际时序**。独立下载 attempt id、原生状态串行与 qid 清理已实现；JS 无法撤销已发出的 RNTP reset/add/play。仍需在真机注入迟到事件、挂起原生回调、杀进程重启。
2. **V2：图片实际缓存**。账号 cacheKey 已加；真实切换账号、相同 URL 不同鉴权图片，以及清理 Expo 内存/磁盘缓存需真机确认。
3. **V3：系统音频中断**。移除了重复 JS 续播；仍需验证来电前暂停、来电期间手动暂停、蓝牙断连、耳机和系统永久中断。
4. **V5：大曲库与长时内存**。本轮限制了下载、转码和封面的一次资源成本；无限分页、超长队列、快照 JSON 序列化仍没有统一全库预算。需用固定数据量记录帧时间、RSS、磁盘峰值和后台耗电，不能宣称“无内存泄漏”。
5. **平台验收**。Android 构建环境缺 Java Runtime 和 SDK；没有伪造 Android 编译结果。iOS 编译通过也不表示弱网真机测试通过。
6. **历史和极端存储失败**。旧版没有完成标记的 Android 中断文件不能安全推断完整性；采用保守恢复/重下。磁盘或 Keychain 全面不可写时无法承诺跨重启撤销成功，界面退出与后续错误仍分别处理。

建议真机矩阵：0 网络/高延迟/丢包/断网重连；加载中连点下一首；登出同时 token 刷新；缓存清空中迟到响应；下载→取消→重试；iOS 后台/被系统杀进程；Android 系统下载失败/复制中断；低磁盘；连续播放与反复切页 60 分钟。每项记录设备、系统版本、服务版本、复现步骤、预期、实际、日志和峰值，未跑记“待验”。
