## 用法

- **Review 时**：按下面清单逐条过。每条都对应一个**本项目真实踩过的坑**，
  不是通用教条 —— 所以请当成硬性要求。
- 单人开发也建议走一遍：写清单的意义就是让「检查」不依赖记忆。

## 0. 提交前必跑（不可跳过）

```bash
node scripts/verify.mjs
```

包含：架构守卫 → 4 包类型检查 → 4 包单元测试（共 9 项，约 40 秒）。

> 不要用 `pnpm -r typecheck` / `pnpm -r test`：本机会报 `EEXIST symlink`。
> `node scripts/verify.mjs` 已绕开 pnpm，本地和 CI 跑的是同一条命令。

**改了原生配置（`app.json` / config plugin / 字体 / 图标）还要额外做**：

```bash
cd apps/mobile && npx expo prebuild --platform ios   # 不要加 --no-install，否则 .xcworkspace 会被删
grep android:usesCleartextTraffic android/app/src/main/AndroidManifest.xml  # 去产物里验证，别信配置
```

> **配置项写进去 ≠ 生效**。Expo 会静默忽略未知的 `app.json` 键。
> 任何原生配置改动都必须去生成的产物里 grep 确认。

## 1. 通用：这次改动会不会静默失效？

这是本项目最高频的失效模式。逐条问自己：

- [ ] **有没有「字符串近似匹配」的判断？** 例如 `message.includes('...')` 用来识别某个错误。
      → 必须去依赖的**源码**里核对原文（RNTP 那次就是少了 `been`，分支从来没生效过）。
      → 建议配一条「读依赖源码核对文案」的测试，见 `player-setup-resilience.test.ts`。
- [ ] **有没有「写进去了但不确定生效」的配置？** → 去产物里验证。
- [ ] **有没有「一次性初始化 + 缓存」的写法？** → 失败时必须把缓存清空，
      否则每个入口 await 它都立刻抛（`ensurePlayer()` 那个坑）。
- [ ] **新加的检查/断言，你验证过它会失败吗？** → 造一个违规样本跑一遍。
      **一条永远为真的检查比没有检查更危险。**

## 2. 播放器 / 原生（最高风险区）

- [ ] **错误处理走 `normalizePlaybackError()`**（`src/player/playback-error-policy.ts`）。
      RNTP 的 `PlaybackError` 两端字段名不一致（iOS 发 `error`，Android 发 `message`+`code`），
      而 JS 类型声明是错的。**iOS 上直接读 `event.code` 恒为 `undefined`**。
- [ ] **新的队列操作传了 `label`**：`queue.run(mutation, { label: 'xxx' })`。
      队列带 30s 看门狗，超时日志靠 label 指认是哪个操作卡住了。
      任何**不 settle** 的 mutation 会永久堵死后续所有播放操作。
- [ ] **触感走 `src/lib/haptics.ts`**，不要就地 `Haptics.impactAsync(...)`。
      现有词汇不够用？**先扩 `haptics.ts`**，不要绕过它。（守卫会拦新增）
- [ ] **转码相关改动**：
  - 分片命名从播放列表读，**不能猜**（真实是 `00000.m4s`，5 位补零）；
  - 404 可重试、410 要重开会话；
  - 下载期间必须持续发心跳（10s），否则约 1 分钟后任务被回收；
  - 产物后缀必须 `.mp4`（沿用源后缀 = 必然播不出来）；
  - 完整性判据要 `moof` 计数 + 时长比对**两个一起用**（缺一不可）。
- [ ] **改播放失败路径时**：必须先作废缓存再重试，否则反复命中同一个坏文件。

## 3. 架构与分层

- [ ] **纯逻辑放在 `*-policy.ts` 里**，不 import RN / Expo，这样单测能直接跑。
      需要持久化的状态放 `*-preferences.ts`（可以有依赖，测试里 mock 掉）。
      （守卫会拦）
- [ ] **新增 provider 能力要走四层**：`capabilities` 声明 → `endpoints` 端点 →
      契约方法 → UI 入口。有 `capability-consistency.test.ts` 兜底。
- [ ] **`capabilities` 要诚实**：后端做不到就别声明 `true`。
      `qualityTiers` 默认 `false` 是**刻意的** —— 飞牛只有一档，绝不该据音质偏好强制转码。
- [ ] **新增路由后重新生成 `.expo/types/router.d.ts`**，不要用 `as never` 糊过去。
      （守卫会检查路由是否都进了 `router.d.ts`）
- [ ] **新增图标**要在 `components/icon.tsx` 的 `ICONS` 里加。

## 4. 测试

- [ ] **断言的是行为，不是源码文本。**
      **判断标准：把被测代码改坏，这条测试会不会失败？**
      不会 → 它保护不了任何东西。
- [ ] `readSource` / `hasCode` 只用于「**禁止**出现 X」这类约束（`hasNoCode`），
      且**断言里不要写换行和缩进**（源码读取会折叠空白）。
      「必须出现 X」的约束优先交给守卫 / lint，而不是测试。
- [ ] 测依赖原生模块的代码时，用现成模式：
      `vi.mock('原生模块')` + `vi.resetModules()` + 动态 `import()` 拿全新模块实例。
      参考 `player-setup-resilience.test.ts`、`transcode-session.test.ts`。
- [ ] **新增了行为测试就顺手把对应的脆性测试删掉**，别让两套并存。

## 5. 类型

- [ ] **不加 `@ts-ignore`**（守卫会拦）。要压制错误用 `@ts-expect-error` ——
      它在错误消失时会自己失败，逼着你回来删掉。
- [ ] **新增 `as any` / `as never` 会被守卫拦下**。如果确实需要：
      - 列表 ref 泛型不匹配这类第三方问题 → 加一行注释说明原因；
      - **路由跳转的 `as never` 是信号**：先检查是不是 `router.d.ts` 没重新生成。
- [ ] 注意 `apps/mobile` 的类型严格度**低于** `packages`（缺
      `noUncheckedIndexedAccess` / `noImplicitOverride` / `verbatimModuleSyntax`）。
      在 `apps/mobile` 里写代码时，不要指望类型系统会帮你抓出索引越界。

## 6. 文档

- [ ] **改了依赖版本 / 脚本 / 目录结构 → 同步更新交接文档。**
      （现在交接文档的技术栈还写着 Expo 53 / RN 0.79，实际是 57 / 0.86 —— 已经误导过一轮了）
- [ ] **踩到新坑 → 写进 `MEMORY.md`**（项目长期记忆），不要只留在提交信息里。
- [ ] **写「为什么」而不是「是什么」**：本仓库注释的价值在于记录了
      「为什么不能用更直观的写法」，这是最该保留的部分。

## 7. 需要拒绝的改动（除非有充分理由）

- 绕过 `haptics.ts` / `playback-error-policy.ts` 等统一出口；
- 在 `src` 下留 `console.log`；
- 用 `as never` 掩盖未重新生成的路由类型；
- 为了「省流量」在飞牛后端上按音质偏好强制转码；
- 给不可播格式沿用源后缀命名缓存产物；
- 在串行队列里跑「可能永远不 settle」的操作而不设超时。

## 附：守卫覆盖了什么、没覆盖什么

| 已自动化（`node scripts/guard-architecture.mjs`） | 仍需人看 |
| --- | --- |
| 触感收口 | 错误处理是否走统一归一化 |
