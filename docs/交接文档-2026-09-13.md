一期共 **~40 个功能项**，2026-09-13 全部完成。主要成果：

- **播放**：本地/远程曲目播放、后台播放、锁屏控制、AirPlay、系统音量同步

## 四、已知的坑（必读，避免踩重复）

### 4.1 本机环境限制

| 限制 | 影响 |  workaround |
| --- | --- | --- |
| **无 JDK / Android SDK / Android Studio** | 无法运行 `gradlew assembleDebug`，无法真机验证 Android | 只能做 `expo prebuild` + 静态核对；真机验证需换机器或配环境 |
| **pnpm 跑 typecheck/test 会触发 `EEXIST symlink`** | 不能用 `pnpm typecheck` / `pnpm test` | **优先用 `node scripts/verify.mjs`**（已绕开 pnpm，本地/CI 同一条命令）；需要单独跑时进包目录用 `node node_modules/typescript/bin/tsc -p tsconfig.json`、`node node_modules/vitest/vitest.mjs run test/unit` |
| **zsh `grep` 不支持 `\|` 交替** | `grep "A\|B"` 恒为空 | 用 `grep -E "A|B"` 或 Grep 工具（ripgrep） |
| **同一文件多条 Edit 并行会静默丢改动** | 返回 success 但文件没变 | 改同一文件必须串行，改完用 Grep 复核 |
| **交付文件放 `~/Downloads/`，不要放 `/tmp`** | macOS `/tmp` 是 `/private/tmp` 软链，Finder 看不到且会被清理 | 用 `open <目录>` 在 Finder 打开 |
| **ffmpeg/ffprobe 在 `/opt/homebrew/bin/`** | `command -v` 会说没有（PATH 问题） | 直接用绝对路径 |

### 4.2 Expo / RN 坑

| 坑 | 说明 |
| --- | --- |
| **配置项写进去 ≠ 生效** | Expo 会静默忽略未知的 `app.json` 键。任何原生配置改动都要去生成的产物里验证（如 `grep android:usesCleartextTraffic android/app/src/main/AndroidManifest.xml`） |
| **`expo prebuild --platform ios --no-install` 会删 `.xcworkspace`** | 它清空并重写整个 `ios/` 目录但跳过 `pod install` → Xcode 构建报 workspace 不存在。**修复**：`cd ios && pod install`。**避免**：用不带 `--no-install` 的版本 |
| **新增路由后 `.expo/types/router.d.ts` 不会自动更新** | 不要 `as never` 糊过去。可离线重新生成（见 MEMORY.md） |
| **RNTP `PlaybackError` 两端字段名不一致** | iOS 发 `{ error }`，Android 发 `{ message, code }`，JS 类型声明是 `{ code, message }`。**统一走 `playback-error-policy.ts` 的 `normalizePlaybackError()`** |
| **播放器链路没有解码器注入点** | iOS = RNTP→SwiftAudioEx→AVPlayer；Android = RNTP→KotlinAudio→ExoPlayer 2。挂自定义解码器要 fork KotlinAudio |

### 4.3 转码与缓存坑

| 坑 | 说明 |
| --- | --- |
| **分片有「还没生成」的竞态** | `POST /track/transcode` 返回 `success` 只代表任务已建，分片可能还没生成 → 请求分片拿到 **404**（播放列表和 `init.mp4` 却能取到）。源越重越容易踩（DSD256 稳定复现，等约 2 秒即好）**404 可重试、410 要重开会话** |
| **真实分片命名 `00000.m4s`（5 位补零）** | 与本地 ffmpeg 样本的 `seg0.m4s` 不同 → **必须从播放列表读，不能猜** |
| **完整性判据要两个一起用** | `moof` 计数（== 非空分片数）抓丢片/重复；时长比对抓顺序错误。缺一不可 |
| **时长容差不能紧** | 服务端重采样误差本身可达 1%（实测 DSD256 → 384kHz 非整数比，短 1.65s，属服务端既有行为） |
| **产物后缀必须 `.mp4`** | 实测同一份字节：`.mp4`/`.m4a`/`.mov` 可播，而 `.wma`/`.ape`/`.dsf`/`.dff`/`.wv`/`.tak`/`.tta` 全部 `isPlayable = false` |
| **写路径不做时长校验** | 顺序由构造保证，列表正确性由下载前的 `validatePlaylistAgainstSource` 挡 |

### 4.4 代码规范

- **纯逻辑一律单独放 policy 模块**（`*-policy.ts` / `*-preferences.ts`），不 import RN / expo，这样单测能直接跑
- **架构契约测试**统一用 `test/support/source.ts` 的 `readSource`（去注释 + 折叠空白），「禁止出现 X」用 `hasNoCode`
- **触感统一走 `src/lib/haptics.ts`** 的 `tap()` / `select()`，不要再各处手写 `Haptics.impactAsync`
- **`AsyncMutationQueue` 必须带看门狗**：队列尾部串在上一个任务上，任何不 settle 的 mutation 会永久堵死后续所有操作

## 十、给接手人的建议

1. **先读 `MEMORY.md`** —— 里面记录了所有踩过的坑和硬规则，比这份交接文档更细
2. **做改动前跑 `node scripts/verify.mjs`** —— 一条命令跑完守卫 + 类型检查 + 单测，全绿再提交。
   不要用 `pnpm -r`（本机会报 `EEXIST symlink`）
3. **改原生配置后必须验证产物** —— Expo 会静默忽略未知键，去 `ios/` 或 `android/` 里 grep 确认
4. **新增能力要走四层** —— `capabilities` 声明 → `endpoints` 端点 → 契约方法 → UI 入口，有 `capability-consistency.test.ts` 兜底
5. **提交前对照 `docs/代码评审清单-2026-09-13.md`** —— 尤其是「这次改动会不会静默失效」那一节
6. ** Android 真机验证是最大未知数** —— 建议优先解决，不要拖到最后
